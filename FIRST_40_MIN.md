# FIRST_40_MIN.md — первые 40 минут БЕЗ СТРАХА (за руку)

Боишься что-то сломать на серваке? Это нормально. Прочитай этот абзац и выдохни:

- **Сеть закрыта 10:00–10:40 — тебя физически никто не может атаковать.** Торопиться некуда.
- **Правило №1: сначала БЭКАП, потом трогаем.** Сделал бэкап → любое изменение обратимо.
- **Правило №2: НИКОГДА не закрывай единственное SSH-подключение и не выключай парольный вход, пока во ВТОРОМ окне не убедился, что ключ пускает.** Это спасает от единственной настоящей катастрофы — залочить себя.
- **Правило №3: сервисы под git.** Сломал патчем → `git checkout` и всё вернулось.

Если держать эти 3 правила — сломать по-настоящему ничего нельзя. Поехали по шагам.

---

## ШАГ 0 (нулевой таск) — пароль. Сначала проверь, нужен ли сброс
Орги пароль не дают. Но часто root доступен через `sudo` и сбрасывать ничего не надо. Проверь:
```bash
sudo -i          # пустило в root (#) ? -> сброс НЕ нужен, иди к ШАГ 1
```
**Если `sudo` просит пароль, которого нет** — сброс через GRUB (только пока сеть закрыта, т.к. нужен ребут):
1. Ребут. На загрузке держи **Shift** (или **Esc**) → меню GRUB.
2. На строке с Ubuntu нажми **`e`** (редактировать).
3. Найди строку, начинающуюся с `linux ... `. В конце её, где `ro quiet splash`, поменяй **`ro` → `rw`** и допиши в конец: `init=/bin/bash`.
4. **Ctrl+X** (или F10) — грузимся в root-шелл без пароля.
5. `passwd ubuntu` (и/или `passwd root`) → задай новый, запиши его.
6. `exec /sbin/init` (или `reboot -f`) — обычная загрузка.

> То же самое на своих Kali — пароль там тоже свой поставьте (бродкаст в подсети, другие команды достучатся).

## ШАГ 1 — зайти и открыть ДВА окна (страховка от залочивания)
На своей Kali:
```bash
ssh ubuntu@<ip_сервака>     # окно A — рабочее
```
Позже, когда будешь трогать SSH, открой **второе окно B** тем же `ssh` и держи его. Пока в B есть живой вход — ты не отрезан, даже если в A всё испортишь.

Поставь софт на сервак:
```bash
sudo apt install -y tmux tcpdump git nftables
```

## ШАГ 2 — БЭКАП ВСЕГО (до любых изменений!)
Это делает всё дальнейшее безопасным. Найди сервисы и забэкапь каждый:
```bash
ss -tulpn                                   # какие порты слушаются
systemctl list-units --type=service --state=running
ls -la /opt /srv /home /var/www             # где лежит код сервисов

./scripts/backup.sh /opt/service1 service1  # для КАЖДОГО сервиса
scp -r /backups <ты>@<своя_kali>:~/backups  # копия на Kali (железо, отката нет!)
```
Сделал бэкап и копию на Kali — теперь даже если угробишь сервак, всё восстановимо.

## ШАГ 3 — сервисы под git (мгновенный откат патчей)
Для каждого сервиса, пока он «ванильный»:
```bash
cd /opt/service1 && git init -q && git add -A && git commit -qm round0
```
Теперь любой патч откатывается одной командой: `git checkout -- . && systemctl restart <svc>`.

## ШАГ 4 — SSH-ключи (ОПАСНЫЙ шаг, делаем в правильном порядке)
Цель: пускать только по ключам пятерых, выключить вход по паролю. Порядок критичен.

1. Собери `*.pub` всех пятерых (каждый на своей Kali: `ssh-keygen -t ed25519`, шлёт тебе `~/.ssh/id_ed25519.pub`).
2. Добавь их на сервак:
```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
nano ~/.ssh/authorized_keys     # вставь все 5 строк .pub, сохрани
chmod 600 ~/.ssh/authorized_keys
```
3. **ПРОВЕРКА ДО выключения пароля.** В НОВОМ окне B с Kali:
```bash
ssh ubuntu@<ip_сервака>         # должно пустить БЕЗ пароля (по ключу)
```
   Не пустило по ключу → **стоп, не выключай пароль**, чини ключи. Пустило → продолжай.
4. Снеси чужие ключи (мог остаться доступ с завода):
```bash
# оставь в authorized_keys ТОЛЬКО ваши 5 строк, лишнее удали
sudo sed -n '1,50p' /root/.ssh/authorized_keys 2>/dev/null   # глянь рутовые тоже
```
5. Только теперь выключаем парольный вход:
```bash
sudo nano /etc/ssh/sshd_config      # PasswordAuthentication no ; PermitRootLogin prohibit-password
sudo grep -riE 'passwordauth|permitroot' /etc/ssh/sshd_config /etc/ssh/sshd_config.d/
sudo systemctl restart ssh
sudo sshd -T | grep -i passwordauthentication   # должно быть: no
```
6. **ПОСЛЕ рестарта — НЕ закрывай окна.** Открой ещё одно, ТРЕТЬЕ окно и зайди. Зашло по ключу → всё ок, можно жить. Не заходит → у тебя ещё открыты окна A и B, верни `PasswordAuthentication yes`, рестарт, разбирайся.

> Это и есть вся «страшная» часть. Сделал по порядку с проверкой во втором окне — залочиться невозможно.

## ШАГ 5 — закрыть лишние порты (БД на localhost)
Не трогай порт сервиса (туда ходит чекер!). Прячь только внутреннее:
```
Postgres  postgresql.conf : listen_addresses = 'localhost'
MySQL     *.cnf           : bind-address = 127.0.0.1
Redis     redis.conf      : bind 127.0.0.1
Mongo     mongod.conf     : bindIp: 127.0.0.1
```
```bash
sudo systemctl restart postgresql   # или mysql/redis/mongod
ss -tulpn                           # проверь: БД больше не на 0.0.0.0
```
Обратимо: вернул конфиг назад → рестарт.

## ШАГ 6 — дефолтные креды
`admin/admin`, `admin` в БД — поменять. **НО сначала проверь, не ходит ли под ними чекер** (вдруг он логинится как admin). Сомневаешься — оставь до первого зелёного раунда, не спеши.

## ШАГ 7 — трафик (Саша Ф, параллельно с 10:00)
```bash
sudo mkdir -p /data/pcap
tmux new -s cap
sudo ./scripts/capture.sh "port 80 or port 5000"   # крутится ВСЮ игру
# Ctrl+b затем d — отцепиться
```

## Что безопасно, а что осторожно (чтобы не бояться)
| Действие | Риск | Откат |
|---|---|---|
| бэкап, git init, tcpdump | нулевой | — |
| `passwd`, добавить ключи | низкий (окна открыты) | вернуть пароль |
| **выключить парольный SSH** | **залочиться** | только пока окна открыты → проверяй во 2-м окне! |
| БД на localhost | низкий | вернуть конфиг + рестарт |
| патч сервиса | можно убить чекер | `git checkout` + рестарт |
| трогать порт сервиса в фаерволе | **убьёшь чекер** | не трогай порт сервиса вообще |

## Если всё-таки что-то сломал
- **Не заходит по SSH, но окно ещё открыто** → в нём верни `PasswordAuthentication yes`, рестарт ssh.
- **Отрезал себя полностью** → физически за сервак, вход с экрана/клавиатуры (это твой ноут), чини локально.
- **Сервис упал** → `systemctl status <svc>`, `journalctl -u <svc> -n50`, `git checkout`, рестарт; не поднимается → из бэкапа (`backup.sh`).
- **Чекер покраснел после патча** → откати патч, сервис важнее дыры.
